Vital follows [semantic versioning](https://semver.org/): `MAJOR.MINOR.PATCH`. The version lives in `apps/web/package.json`. The page footer reads the latest GitHub release and links to it, next to the CI status on `main`.

The line starts at **0.1.0**. `1.0.0` is a stable product, not the first demo. The tag `v1.0.0` already on `main` is that first demo — leave it, and do not bump from `1.0.x`. The number in `package.json` is the current version.

| Change | Bump | Example |
|--------|------|---------|
| Fix, copy, or style | Patch | `0.1.1` |
| New feature | Minor | `0.2.0` |
| Breaking change while the major is still 0 | Minor | `0.2.0` |
| Stable release, or a break after `1.0.0` | Major | `1.0.0` |

## Release notes

Same shape every time. Write them by hand. The tag name is `vX.Y.Z`.

```md
## Summary

- One to three bullets a person can read without the diff.

**Full Changelog**: https://github.com/vitalvie/vital/compare/vPREV...vNEXT
```

## Ship a release

<Steps>
  <Step title="Bump the version">
    On a branch from `develop`, update `version` in `apps/web/package.json`, then merge the PR once CI (including evals) is green.
  </Step>
  <Step title="Merge develop into main">
    Open a PR from `develop` to `main` and merge it with a merge commit.
  </Step>
  <Step title="Tag and publish">
    ```bash
    git checkout main && git pull
    git tag v0.1.1 -m "One-line summary"
    git push origin v0.1.1
    gh release create v0.1.1 --title "v0.1.1" --notes-file notes.md
    ```
  </Step>
  <Step title="Deploy">
    ```bash
    pnpm run deploy
    ```
    The script refuses to run unless you're on a clean `main` whose `HEAD` carries the tag matching the version. The Worker version is tagged the same way.
  </Step>
</Steps>

## First-time setup

```bash
cd apps/web
pnpm exec wrangler login
```

The Worker serves the web app and forwards `/api` to the Python API (`apps/api`), which this script does not deploy. Locally, `pnpm dev` reads `OPENROUTER_API_KEY` from `apps/web/.env`. Set a spending limit in the [OpenRouter console](https://openrouter.ai/settings/credits).

## Host the API

The API ships as a container. Run it on any host that gives it an HTTPS address.

```bash
docker build -f apps/api/Dockerfile -t vital-api apps/api
```

Set these on the API host: `OPENROUTER_API_KEY`, `PROXY_SECRET` (a long random string), and optionally `OPENROUTER_MODEL`, `VOXTRAL_VOICE`, the Langfuse keys and the rate limits. The host provides `PORT`.

Then tell the Worker where the API is, once:

```bash
cd apps/web
pnpm exec wrangler secret put API_URL        # https://your-api-host
pnpm exec wrangler secret put PROXY_SECRET   # the same value as on the API host
```

Check `https://<site>/api/health` after a deploy. It answers `{"ok": true}` when the Worker reaches the API.

## Roll back

```bash
cd apps/web
pnpm exec wrangler deployments list
pnpm exec wrangler rollback <version-id>
```
