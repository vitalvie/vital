## Flow

1. **Record.** Tap the mic to start, tap again to send. The browser records with `MediaRecorder`.
2. **Transcribe.** The `transcribe` server function sends the audio to **Voxtral Mini Transcribe** (`voxtral-mini-latest`).
3. **Answer.** The `askVital` server function builds a context from the health data (with the demo values set in the UI) and the Body Battery score, then calls Mistral chat.
4. **Speak.** The `synthesize` server function turns the answer into speech with **Voxtral TTS** (`voxtral-mini-tts-2603`). The browser plays the MP3. Tapping the mic while it speaks stops it.

All Mistral calls use the official SDK (`@mistralai/mistralai`) on the server. The API key never reaches the browser.

## Voice

Voxtral TTS uses a preset voice, `gb_jane_neutral` by default. Change it with `VOXTRAL_VOICE` in `apps/web/.env`. Other presets include `en_paul_neutral`, `gb_jane_confident`, `gb_oliver_confident`, and `fr_marie_happy`.

## Answer rules

The system prompt in `apps/web/src/server/assistant.ts` keeps answers demo-friendly and safe:

- 2 to 3 short sentences, plain text, because they're read aloud
- Describes how today compares with their usual, as a reading of the data, not a medical instruction
- One everyday habit, such as a bedtime or an easier effort, never a treatment
- Stays on sleep, recovery, activity and energy
- Never diagnoses, names conditions, or gives medication or doses, and suggests a professional instead
- Redirects emergencies to 112

See [Safety and evals](/safety) for every guardrail and how they're tested.

## Example

> **You:** Should I train hard today?
>
> **Vital:** This looks like a heavier day than usual, after a short night. An easy walk would suit you better than a hard session.

<Note>
  Browsers only allow the microphone on HTTPS or `localhost`. To use another device, serve the app over HTTPS (for example `tailscale serve --bg 3000`). Otherwise, on a plain HTTP address, use the suggested questions or the text box. The answer is still spoken by Voxtral.
</Note>
